## 3. 在原机实际尝试建完 E5 和 Qwen

1. 用两个 `--status` 命令和 manifest 核查 `data/course-full/documents.sqlite`、`indexes/course-full/`、`indexes/course-full-vectors/`、`indexes/model_cache/`。核对语料来源 `Tevatron/browsecomp-plus-corpus`、train split、修订 `b27b02bc3e45511b8b82a13e6f90ce761df726f6`、语料指纹、900 字符分块和 150 字符重叠。若沿用上轮原样语料，指纹应为 `ea8764233b0d4a76d050842e290805a0f154858084dfd0430ba8c0d9c555025f`。核查已完成分片、是否有其他进程占用索引、SQLite WAL 状态、BM25 相对链接、模型和 tokenizer 缓存、可用磁盘与设备内存。以实际最新清单为准。
2. **实质尝试两路。** E5 是第二类，目标使用 `intfloat/e5-small-v2` 固定修订 `ffb93f3bd4047442299a41ebb6fa998a38507c52`。Qwen 是第三类，目标使用 `Qwen/Qwen3-Embedding-0.6B` 固定修订 `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`。先在现有机器验证兼容后，从已保存的分片继续。在原机用真实代表片段分别跑短批，报告源片段每秒、显存或统一内存峰值、分片大小、读写与剩余空间。若内存稳定，让 E5 在 CPU 或可用设备批量续建，并尽早试 Qwen。新脚本可每进程构建多个分片，Qwen 可先试 1，再逐步试 2 或 4。调高批量和并行前看实测；两路同跑时监控内存争用。两类嵌入使用本地模型，不需要 LLM API。
3. 优先复用最高进度的兼容检查点。MPS 内存不足时调小 batch 和每进程分片数，保留已写分片，测 CPU 或可用 CUDA。编码模型、分块、片段 ID 与原文坐标要和既有分片兼容。配置、语料或模型不兼容时使用独立目录，说明不能续用的原因。若需要 GPU，请把设备、工具链、所需空间和实测时间外推写给 ddg，由 ddg 去找机器。卡住时要回传有效分片、最小复现、最近成功进度和下一条构建命令，并继续完成可独立执行的测试。
