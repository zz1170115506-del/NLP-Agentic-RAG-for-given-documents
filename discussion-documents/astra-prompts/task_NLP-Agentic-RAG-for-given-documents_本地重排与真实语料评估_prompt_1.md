# Astra 长任务：实现本地重排并用真实语料评估

## 任务目标

请在现有仓库上完成一轮可复现的检索优化。实现可关闭的本地 Cross-Encoder 重排，使用真实课程语料验证，并用配对实验判断：在同一候选池中，重排能否把关键证据推入最终 top_k？它对延迟、答题准确率和 API 用量有什么影响？如果没有收益，请用实际候选、排名和错误案例解释原因。

这是执行任务。请先阅读适用的仓库说明与代码，然后完成实现、测试、实验、结果报告及功能分支提交。遇到资源限制时，按下文的实验分层完成可运行部分，并给出可复现的剩余步骤。

## 一 实现本地重排

在 `SearchService` 的 hybrid 路径把重排放在片段级 RRF 之后、最终 top_k 之前。仍使用现有统一 `search`，CLI、现有系统和同僚后端可通过同一配置启用。

1. 首个重排候选使用 `cross-encoder/ms-marco-MiniLM-L6-v2`，在本地用真实权重给 query–passage 对打分。查阅[官方模型说明](https://huggingface.co/cross-encoder/ms-marco-MiniLM-L6-v2)和[对应 tokenizer 配置](https://huggingface.co/cross-encoder/ms-marco-MiniLM-L6-v2/blob/main/tokenizer_config.json)。优先复用仓库已有的 Transformers/PyTorch 依赖。记录实际加载的模型、tokenizer revision、设备及批大小。
2. 重排默认关闭，关闭且使用原候选深度时，保持当前查询的结果、顺序和分数语义。独立配置每路召回深度与重排深度。它们都与外部 top_k 不同。模型延迟加载，普通查询和禁用配置可以沿用已有环境与索引。配置校验应覆盖深度、批大小和设备的边界。
3. 只使用当前 search 收到的查询和候选原文。先从 RRF 获取一个有限候选池，再对配置指定的前缀打分。使用可解释的顺序处理重排后的候选和未经重排的尾部。保留基线 RRF 排名和重排排名以便诊断，避免把两种不同量纲的分数直接相加。相同重排分数用原 RRF 排名稳定打破平局。最终 score 为有限数值，文档说明分数的用途。
4. 显式验证 query、passage 和特殊 token 的合计长度。需要切窗时，从原文位置切出连续窗口，限制每个候选的窗口数，记录窗口分数如何汇总及覆盖限制。返回完整原块时保留原块坐标。如果返回实际用于打分的子窗口，按子窗口重新计算 start/end，并保留所属 chunk_id。对极长查询或无法推理的候选采用清楚、可测试的处理规则。
5. 开启重排遇到缺失权重、初始化失败、无效分数或设备错误时，提供可定位的错误。实验记录必须能区分成功重排、显式降级与失败。任何降级路径都要在结果中标明，便于排除受影响的对照数据。
6. 同一候选在多路出现时沿用片段级 RRF 合并。不同 chunk 即使来自同一文档，也保持独立。主对照中固定重复片段处理规则，把新增重叠抑制单独列为后续变量。

## 二 保护已交付的 Agent 接口

仓库已有 `rag_agent.peer_backend:create_backend`。保留工厂和这三个同步函数的现有签名、返回规则及异常边界。

| 接口 | 核对事项 |
| --- | --- |
| `search(query, top_k=5)` | 有序平面 `list[dict]`。每条包含 `doc_id/chunk_id/score/snippet/source_url/start/end`。top_k 按片段计数，允许重复 doc_id。无命中返回空列表。 |
| `open_document(doc_id, start=0, length=6000)` | 返回同一文档的实际原文范围。文档尾部返回实际 end。 |
| `find_in_document(doc_id, query, window=250)` | 按现有字面匹配规则返回原文窗口及范围，保持无匹配的返回形态。 |

每个 search 结果应满足 `document.text[start:end] == snippet`，范围使用 Python 原字符串的字符坐标，左闭右开。检查 Unicode、文档尾部及同文档两段不重叠的证据。保持工具只有一个 search。重排发生在工具内部，沿用现有工具调用统计口径。

同僚确认选入模型上下文的证据将携带 `chunk_id/start/end`。如可使用实际同僚代码，可额外做集成烟测。检索侧契约通过和 Agent 实际上下文联调通过分别记录。

## 三 固定对照变量与实验样本

请先冻结基线和样本，再比较重排。保留检索方式、语料 revision、索引及 embedding 模型、查询文本、最终 top_k、硬件和运行预算。输出为每次运行使用独立目录，记录仓库 SHA、配置指纹、样本清单、索引版本、模型 revision 和运行时间。

| 实验组 | 操作 | 用来回答 |
| --- | --- | --- |
| A 原始基线 | 保持当前每路候选深度，仅 RRF | 现有代码的排序与成本 |
| B 候选深度对照 | 设置新的固定深度，仅 RRF | 候选池扩大本身是否改善结果 |
| C 重排对照 | 使用 B 的同一份 RRF 候选池，开启重排 | 重排本身改变了什么 |

候选深度可从每路 50、重排 RRF 前 30 开始。如果当前候选池够用，先用原深度做 B/C；此时 A 和 B 可合并。参数是起点。记录最后选择和资源依据。优先让 B、C 消费同一个候选快照，或核对两组在重排前的候选 ID 与顺序一致。对照查询中如果有某路失败，记录到每题并从有效配对结果中辨认出来。

### 阶段 1 合成数据与可控回归

用合成语料跑通完整代码路径，验证开关、平分、候选不足、无结果、片段身份、原文范围和错误路径。可使用测试替身验证排序逻辑。另用真实重排模型跑少量 query–passage 对，验证权重加载、成对编码、打分和排序。明确区分接口回归与真实模型运行。

### 阶段 2 真实课程语料检索

使用 [BrowseComp-Plus 固定语料](https://huggingface.co/datasets/Tevatron/browsecomp-plus-corpus)。优先复用配置相符的现有三路索引。如果没有可用索引，使用单独的目录和配置，固定真实语料 revision，先做小样本三路建库并测资源，再在合理预算内扩大。若只能建立真实 BM25 索引，可在实验入口用同一个重排器对固定 BM25 候选打分。将此结果标为真实语料上的 BM25 排序实验，并给出扩展到真实三路混合的步骤。

提前固定查询样本和证据标注。课程验证题仅在对应证据确实落在该检索语料范围内时用于解读证据排序。若使用小语料切片，可另做独立的小样本标注，记录相关文档及必要的片段范围、至少几个有迷惑性的候选，以及样本是如何选出的。区分文档级与片段级标注。只在有相应标签时计算 Recall@k、MRR 或 nDCG；否则报告有实际依据的命中数量、排名变化和案例。

所有标签及参考答案仅由评估逻辑读取。重排输入只包含查询和候选原文。保留一小组未用于调参的题目做最终对照。样本实验按实测语料和题数报告，整个课程语料的性能结论需要对应的全量实验支持。

### 阶段 3 少量真实 DeepSeek 端到端对照

从执行环境的项目 `.env` 读取 `LLM_API_KEY`，沿用仓库的 provider 配置及模型身份检查。课程 Agent 使用指定 DeepSeek-V4-Flash。Astra 用于开发和实验执行。

有可用密钥、已确认的模型映射和足够的索引覆盖时，先选约 5 道验证题做 B/C 配对运行，最多 10 道。记录实际题数和每组用量。两组使用同一 Agent 版本、同一模型、同一问题、同一预算与参数。Agent 在重排后可以选择不同的下一步查询，这是端到端效应。配对检索实验仍单独负责隔离排序收益。扩大到完整课程验证集或多次重复调用前，先把样本的实际成本和时间估算交给负责人决定。

沿用独立评测入口计算 normalized EM，统计真实工具调用和 API `usage.total_tokens`，报告失败、超时和缺失 usage。至少保留可定位失败的运行记录。如果密钥、API、指定模型部署或语料覆盖不足，继续完成阶段 1–2，并写出阶段 3 的复现命令及具体限制。

## 四 结果归因

在实验报告中至少回答以下问题，并附实际配对结果。

- 有多少题的关键证据在召回候选中？有多少从 top_k 外进入了 top_k？有多少从 top_k 掉出？
- 关键证据没有进入候选池的题目，有多少是数据覆盖不足，有多少是检索漏召回？分别指出可复核的证据。候选中已有相关证据的题目，解释 RRF 或重排的排序变化。
- top_k 中重复或高度重叠的片段是否挤占了不同证据？区分重复内容与同文档的独立证据。
- 记录候选数、召回与融合耗时、重排耗时、端到端延迟及失败数。区分首次模型加载和预热后的延迟。题数太少时提供逐题耗时或中位数，说明高分位统计的样本限制。
- 有真实 Agent 对照时，报告 normalized EM、工具调用数、API token、失败数和实际配对题数。保留一两个改进案例和一个退化或无效案例，注明真实原因或合理推断。
- 根据结果给出推荐。关键证据常在池中但排名低，优先优化排序。关键证据经常未召回，优先研究候选深度、查询或分块。结果不明确时，指出最能区分两种解释的下一轮实验。
