# Qwen3-Embedding-4B 九题真实问答复测：256 维与 2560 维 int8

2026 年 11 月 17 日 · 百炼北京 · 固定九道验证题

**把实际检索从 256 维提高到 2560 维，两轮都答对 3/9，命中的都是第 64、231、788 题，其余六题均弃答。** 第 58 题的资助段仍排不进前五。第 788 题的医院反证首次在这两轮对照中进入前五，随后在组织模型请求时丢失。两个案例需要修复的是不同步骤。

## 两条最重要的证据

### 第 58 题：论文找到了，奖名和编号始终没有返回

文档 28406 的字符区间 `[38992,39072)` 是包含奖名和编号的完整原句。它位于长达数万字符的论文末部。识别论文、看到目录里的“资助”或打开同一论文的其他记录，都不足以回答奖名。

| 实际问答 | 资助原句所在段在候选中的去向 | 模型最终看到什么 |
|---|---|---|
| 256 维 | 第 4、5 次搜索完整覆盖原句。关键词排名第 1、13，经向量重排后为第 31、30。第 6 次只覆盖 72/80 字符，排第 20。 | 6 次全库搜索都没返回资助原句，最终弃答。 |
| 2560 维 | 第 2、3、5 次搜索完整覆盖原句。关键词排名第 29、30、28，经向量重排后为第 **26、25、31**。 | 5 次全库搜索、1 次打开文档。打开的是文档 4619 的开头。没有在文档 28406 内搜索致谢，4 次模型请求均看到 **0/80** 个目标字符，最终弃答。 |

两轮这道题的查询没有一条逐字相同，因此不能把两列名次的变化解释成单独提高维度的效果。可以确定的是，两轮都把含完整答案的段落留在了前五之外。论文身份已经明确时，直接在该篇全文中查找资助或致谢，是这道题最值得验证的修复。

### 第 788 题：医院反证从“搜不到”变成了“搜到后没交给模型”

文档 57904 的 `[586,684)` 明确记载 Hamidia Hospital 在 **1927 年前已接诊**。这能排除把这家医院认作题目所说的“1930 年后成立的医院”。要判断附近是否另有符合条件的医院，还需要核实医院身份和距离。

| 步骤 | 256 维 | 2560 维 |
|---|---|---|
| 医院原句进入候选 | 7 次搜索均未进入 32 段候选。 | 第 7 次搜索关键词排第 1，重排第 **5**。第 9 次再次进入，重排第 7。 |
| 工具返回及模型可见性 | 工具未返回，模型未见。 | 第 7 次搜索在工具事件 24 返回 E24，原句 **98/98** 个字符齐全。下次请求 28 和最终请求 36 均为 **0/98**，两次请求的字符预算省略名单都明确列出 E24，最终没有引用。 |
| 邻近清真寺的年代 | 记载邻寺建于 1860 年的片段排第 6，未返回。 | 排第 5 并返回。请求 28 看到了完整年代句，到最终请求 36 已全部丢失。 |
| 最终解释 | 名称命中；把 1847 年写成晚于 1930 年，还把从邻寺出发的距离套到目标地点。 | 名称命中。面积和容量有原文支撑，模型明确承认步行距离未核实；医院年代反证和目标建筑的完工条件仍未解决。 |

该题两轮只有两对查询完全相同。新轮最终解释更谨慎，但没有证据表明模型识别和处理了医院反证。验收这类修复时，应同时检查“反证是否进前五”“下一次请求是否带上原句”“最终解释是否据此判断”。

## 真实运行、排序和开销

相同的 100,195 篇文档共切成 4,345,592 段。每次先由 BM25 按词匹配选 32 段，本机 Qwen 再用向量相似度返回前 5 段。int8 表示每个向量分量用一个字节保存，另为每段保存一个 4 字节缩放值。只编码实际进入候选池的段落。两轮使用同一固定版本的 Qwen、同一百炼北京问答模型 `deepseek-v4-flash-0731`、同一题序、提示词、工具和预算；逐题首次请求也分别完全相同。唯一的有效配置差异是 `qwen4b_dimension`。

| 九题实测 | 256 维 int8 | 2560 维 int8 |
|---|---:|---:|
| 答案命中 / 弃答 | 3 / 6 | 3 / 6 |
| 百炼请求成功数 | 37/37 | 40/40 |
| 工具调用（全库搜索 + 打开文档） | 56（52 + 4） | 63（62 + 1） |
| 输入 / 输出 token | 162,396 / 6,560 | 184,955 / 7,322 |
| 总 token | 168,956 | 192,277（+13.8%） |
| 九题逐题耗时之和，排除启动 | 310.22 秒 | 320.17 秒 |
| 编码的不同片段 / 每段向量字节 | 858 / 260 | 996 / 2,564 |
| 实际向量数据 / 含标识的 NPZ 文件 | 223,080 / 303,020 字节 | 2,553,744 / 2,646,380 字节 |

本轮在 Mac GPU 上加载权重并完成模型预热用了 530.78 秒，期间 macOS 还原了本机的部分 Python 依赖文件。这笔一次性启动耗时单独列出。每段向量存储量提高到 **9.86 倍**。token 是服务方报告的文本用量，实际账单金额没有核验。

- **同一轮内对照浮点向量。** 对每个真实查询及其固定候选池，2560 维 int8 与全维浮点参考的前五成员重合 **308/310**，62 次搜索的第一名全部相同。上一轮 256 维 int8 与全维浮点参考重合 **118/260**，52 次中有 22 次第一名相同。原始浮点排名仅供测量，实际工具返回使用 int8 排名。
- **跨轮比较同查询。** 两轮只有 15 对同题、同查询、同顺序候选池的真实调用。它们的前五成员共重合 **37/75**，第一名相同 **5/15**。其余调用沿不同问答轨迹展开，不能把全部差异单独归因于维度。
- **结论适用范围。** 九道固定诊断题逐题得分均未翻转，每种配置各跑一次。此次结果支持“2560 维更接近全维浮点排序”，没有观察到答案命中率收益。第 58 题值得优先验证文内查找，第 788 题值得优先验证反证在下一轮和末轮的保留。
