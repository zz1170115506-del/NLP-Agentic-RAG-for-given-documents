# 九题比较与三类证据问题

同一百炼问答模型从空状态完整运行九题。旧 BM25 方案和本次压缩 Qwen 重排均为 **3/9 答案匹配、6 题弃答**。231 从弃答变为匹配，58 从匹配变为弃答，64 和 788 保持匹配。第 64 题的人口排名获得了直接出处，第 788 题虽然答案字符串匹配，解释仍违反医院成立时间条件。

## 九题逐题证据判断

池内排名均从 1 开始。每次完整 BM25 索引返回 32 个候选，实际交给模型 5 个。下表判断同时参考真实工具返回、最后一次实际 API 请求及模型解释。代码里的检索状态和模型自己声称已经看见某事实，都不能独立证明原文确实传入。

本次三个非空回答共有 9 个引用。独立检查确认这 9 个引用都与固定语料的文档、字符位置及原文一致，最后实际请求也包含对应原文。旧轮的 12 个引用得到同样核验。231 和 788 的具体反例表明，正确的原文引用仍可能配上未经验证的结论。[引用逐条核对](citation-check.json)

## 哪个环节发生了变化

- **关键原文能否检回。** 14 个事先固定的历史诊断范围覆盖九题。其中包括事后借助历史参考定位的段落、相互重叠的资助范围以及反证。旧轮完整检回 6 段、部分检回 1 段、未检回 7 段。新轮分别为 2、1、11。这个清单用于定位已知缺口，不能代表语料召回率。64 的新人口排名出处就在这 14 个范围以外。
- **检回原文能否进入最终请求。** 新轮已检回的三个历史定位点在最终请求中都保留了实际检回的范围，另 11 个定位点在工具返回阶段已经缺失。在定位清单以外，788 的 E12 则有清楚的“已检回、下一请求可见、最后消失”记录，说明跨段条件遗漏仍存在。
- **条件与反证怎样影响最终判断。** 64 的新证据加强已有回答，231 的曲名与合作人有出处，但收录关系和部分人物经历未获原文支持。788 暴露日期先后与距离起点误用。空答中，58 和 390 明确指出缺少回答所需的最后关系，但当前检索路径没有取得能补上该关系的原文。

## 压缩与开销

52 次真实搜索共排序 1,664 个“查询 × 候选片段”记录，实际返回 260 个位置。原始 2,560 维浮点与前 256 维浮点的前 5 成员重合 119/260。固定在 256 维之后，浮点与 int8 的成员重合 259/260，同为首位的有 49/52 次。这里改变候选组成较多的步骤是截取维度。58 的资助片段仅用全维时也在返回深度之外，故不能把这道退化的全部原因归于降维或量化。

问答输入加输出用量从 192,021 降到 168,956 token，少 23,065（12.0%）。实际 API 次数从 41 降到 37，工具从 62 降到 56。新轮累计本地检索时间 213.57 秒，其中向量编码计时 182.08 秒，编码片段 858 次，另有 806 次候选从本地向量缓存复用。计时是这些调用的汇总，token 是问答服务商记录的用量，两者不能直接换算金额。

目前证据支持在这一批查询上用 int8 保存 **256 维**向量，前 5 成员的变化较小。是否应把 2,560 维降到 256 维、是否值得以此路线替换原检索，仍需关注同池漏掉的关键片段和独立问题上的效果。只有压缩排序参与了这一次完整问答；另外两套浮点排序仅用于同池比较。
